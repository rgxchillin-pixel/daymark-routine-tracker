DAYMARK · ONE-TIME SETUP

Sync your routines across devices

Daymark uses Firebase to manage sign-in and save your routines, settings, and progress to your account. You’ll need to create a Firebase project once before the account buttons can work.

  1. Open the Firebase Console, sign in, and create a project.
  2. In Project settings → General, add a Web app and copy its Firebase web configuration.
  3. In Authentication → Sign-in method, enable Google and Email/Password. Google sign-in uses Google’s own secure sign-in. Email/password creates a separate Daymark password.
  4. In Authentication → Settings → Authorized domains, add daymark-6.netlify.app and rgxchillin-pixel.github.io. Add your own domain too, if you use one.
  5. Create a Cloud Firestore database. In its Rules tab, paste the rules from the included firestore.rules file and publish them. They restrict each account to its own data.
  6. Put the Web app config in firebase-config.js in the site files:
window.DAYMARK_FIREBASE_CONFIG = {
  apiKey: "your-web-api-key",
  authDomain: "your-project.firebaseapp.com",
  projectId: "your-project-id",
  appId: "your-web-app-id"
};

Enable the AI Routine Coach

  1. In Firebase, open AI Logic → Get started and choose the Gemini Developer API.
  2. Register the same Web app under App Check → Apps with reCAPTCHA v3. Add the live website host names to that provider.
  3. Paste the public reCAPTCHA site key into window.DAYMARK_AI_CONFIG.recaptchaSiteKey in firebase-config.js. Never use a secret key or debug token in the website.
  4. After App Check works on the live hosts, enforce Firebase AI Logic under App Check → APIs.

The first time someone asks the Coach for an AI reply, Daymark asks permission to send their message and a compact routine summary to Gemini through Firebase. Their name and email are excluded. Health and urgent-safety queries stay on the device. Review Firebase / Google Cloud quotas and billing before public use.

Publish the changed site files. Then sign in while online. The first account on an existing browser keeps its saved routines and uploads them; later edits sync to other devices signed in to the same account.

Keep passwords private. Firebase web configuration is public project information. Never place a service-account file, private key, Google password, or email password in the site source.
